# Sanity TypeGen Integration

This document describes the type-safe Sanity CMS integration using Sanity TypeGen.

## Overview

Sanity TypeGen automatically generates TypeScript types from your Sanity schema, providing end-to-end type safety for all CMS content.

## Generated Types Location

- **Source**: `/sanity/sanity.types.ts` (auto-generated by Sanity CLI)
- **Copied to**: `/src/lib/sanity-types.ts` (used by the application)

## Available Types

The following types are generated and exported:

### Document Types
- `Post` - Blog posts with title, content, tags, etc.
- `Project` - Portfolio projects with description, images, etc.
- `Tag` - Tags for categorizing content
- `Employment` - Employment history records

### Supporting Types
- `BlockContent` - Rich text content blocks
- `Slug` - URL-friendly slug fields
- `SanityImageAsset` - Image assets with metadata
- `SanityImageCrop` - Image cropping data
- `SanityImageHotspot` - Image focus point data
- `AllSanitySchemaTypes` - Union of all schema types

## How to Use

### 1. Client-Side Queries (Solid.js Components)

```typescript
import { createSanityQuery } from '@/hooks/use-sanity-content';
import type { Post } from '@/lib/sanity-client';
import { listPosts } from '@/lib/sanity-queries';

export function PostList() {
  const [posts] = createSanityQuery<Post[]>(listPosts(), {});

  return () => {
    const postData = posts();
    if (!postData) return <div>Loading...</div>;

    return (
      <div>
        {postData.map((post) => (
          <article key={post._id}>
            <h2>{post.title}</h2>
            {/* TypeScript autocompletes all Post fields */}
          </article>
        ))}
      </div>
    );
  };
}
```

### 2. Server-Side Queries (TanStack Start)

```typescript
import { fetchSanityContent } from '@/lib/sanity-server';
import type { Post } from '@/lib/sanity-client';
import { listPosts } from '@/lib/sanity-queries';

export async function getPosts(): Promise<Post[]> {
  return fetchSanityContent<Post[]>(listPosts());
}
```

### 3. Direct Client Usage

```typescript
import { getSanityClient } from '@/lib/sanity-client';
import type { Project } from '@/lib/sanity-client';

const client = getSanityClient();
const projects = await client.fetch<Project[]>(
  '*[_type == "project"] | order(_createdAt desc)'
);
```

### 4. Type Narrowing with Union Types

```typescript
import type { AllSanitySchemaTypes } from '@/lib/sanity-client';

const doc = await client.fetch<AllSanitySchemaTypes | null>(
  '*[_id == $id][0]',
  { id }
);

if (doc?._type === 'post') {
  // TypeScript knows this is a Post
  console.log(doc.title);
}
```

## Regenerating Types

When you update your Sanity schema, regenerate the types:

```bash
# From the /sanity directory
cd sanity
bun sanity typegen generate

# Copy to src/lib
cp sanity.types.ts ../src/lib/sanity-types.ts
```

Or use the automated script:

```bash
# From project root
./scripts/regenerate-sanity-types.sh
```

## Type Safety Benefits

1. **Autocomplete**: IDE autocomplete for all content fields
2. **Compile-time errors**: Catch typos and missing fields before runtime
3. **Refactoring safety**: Rename fields with confidence
4. **Documentation**: Types serve as living documentation
5. **Reduced bugs**: Impossible to access non-existent fields

## Best Practices

1. **Always use type parameters** when calling fetch functions
2. **Handle optional fields** - all content fields are optional in Sanity
3. **Expand references** in your GROQ queries when needed
4. **Regenerate types** after schema changes
5. **Commit generated types** to version control for team consistency

## Troubleshooting

### Types not updating
- Regenerate types: `cd sanity && bun sanity typegen generate`
- Restart TypeScript server in your IDE

### Type errors after schema changes
- Regenerate types
- Update GROQ queries to match new schema
- Check for breaking changes in projections

### Import errors
- Verify `src/lib/sanity-types.ts` exists
- Check that types are exported from `sanity-client.ts`
- Restart TypeScript server
